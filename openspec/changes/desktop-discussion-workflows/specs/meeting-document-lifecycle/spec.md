# 会议双稿与输出生命周期

## Purpose

F015 保存会议角色发现、记录与纪要分离、来源变化提示、本地定稿索引和 PDF 的完整增量语义。会议业务文件属于用户资料，所有操作须按用户明确目标进行，不把材料浏览、状态刷新或文档迁移当作正文写入授权。

## ADDED Requirements

### Requirement: F015 角色发现与清空旧会议关系

打开会议 SHALL 优先验证本会议清单中的路径，再查找标准名或日期前缀的会议记录／纪要；只能采用唯一明确匹配，不改名、不把转写当记录。新会议清空前一会议临时角色，缺失角色显式为 null。

#### Scenario: 缺失或多份角色候选

- **WHEN** 进入新会议且未找到纪要或找到多个记录文件
- **THEN** 返回缺失或候选并等待明确选择，不复用上一会议角色、不随机打开、不自动创建空稿。

### Requirement: F015 显式登记与并发保护

会议文档 SHALL 先通过文档服务保存，再按实际路径及版本显式登记角色和绑定；同会话操作与同真实会议目录修改须串行且带内容版本校验。保存成功但登记失败须保留文件并报告 saved_path。

#### Scenario: 两会话修改同会议

- **WHEN** 两个会话基于同一旧版本更新角色或元信息
- **THEN** 后到冲突明确拒绝，不覆盖较新会议信息；不能用重试创建重复文档规避失败。

### Requirement: F015 来源指纹和过期状态

系统 SHALL 分别记录会议记录指纹、纪要所依据的记录指纹／版本及 PDF 所依据的纪要指纹。记录变化只标纪要过期，纪要变化只标 PDF 过期；旧数据无依据标未核验，用户明确重整才改正文。

#### Scenario: 源记录修改

- **WHEN** 已生成纪要后记录发生变化
- **THEN** 纪要提示过期但正文不自动重写；核验来源也不改变当前固定目标。

### Requirement: F015 元信息与来源引用

共享元信息变更 SHALL 标记需要同步的角色，不自动改正文；来源关联保留材料 ID、字符范围或图片 ID，不推定已核验。关联节点消失应标记待检查，并保留 phase、info、sourceLinks、pendingSync、pdf 等原有信息。

#### Scenario: 元信息或关联变化

- **WHEN** 用户更正时间或文档删除了被引用节点
- **THEN** 分别记录待同步或待检查状态，不编造负责人、截止日、决定或来源证据。

### Requirement: F015 本地定稿索引与部分成功

定稿 SHALL 仅表示本地 published 状态，并在工作区内上级 README 的可识别会议索引更新本会议一行，使用实际相对路径并保留其他内容。没有可识别索引返回 INDEX_UNAVAILABLE，不重写整页；meeting_saved 与 index_saved 分别报告。

#### Scenario: 正文已存但索引不可写

- **WHEN** 定稿文件保存成功，索引缺失或写入失败
- **THEN** 返回部分成功并保留正文，允许修复索引后重试；不得回滚已保存正文或宣称已经对外发布。

### Requirement: F015 PDF 只来自当前已保存纪要

导出 SHALL 使用已保存登记纪要及其预期版本，输出前后核验来源指纹。源文变更必须拒绝登记过期 PDF；默认生成带后缀文件，显式覆盖失败时保留旧 PDF。

#### Scenario: 导出期间编辑纪要

- **WHEN** 后台 PDF 生成后发现纪要版本已改变
- **THEN** 拒绝把旧内容 PDF 登记为当前输出并说明需重新导出。

#### Scenario: 损坏输出或取消

- **WHEN** 浏览器缺失、超时、取消或生成空／非 PDF 文件
- **THEN** 返回具体错误，不能登记成功；只清理本次临时文件，原文件不变。
