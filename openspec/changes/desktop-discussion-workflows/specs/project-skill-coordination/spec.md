# 项目与工作区技能协作

## Purpose

F017 迁移项目主文档、结构化数据、任务拆解、进展和周报的通用协作约束。实际项目文档、路径、技能名称与业务记录保持在用户工作区；本公开规格仅定义发现和调用边界，不复制个人内容或把历史可行性样本当运行验收。

## ADDED Requirements

### Requirement: F017 工作区规则与目标分离

项目场景 SHALL 固定主文档，把项目 JSON、表格和报告作为参考；具体流程从当前工作区 AGENTS、Skill 与桥接工具发现，不硬编码个人磁盘路径或复制其配置。缺集成仍允许普通讨论；不得新增任意 shell 执行工具绕过现有受控接口。

#### Scenario: 进入不同项目

- **WHEN** 项目工作区提供不同文档、规则和工具
- **THEN** 按当前规则定位主文档和材料，普通浏览不改目标；没有所需桥接时说明边界，不假装可用。

### Requirement: F017 任务与进度事实保护

任务拆解、分派、WBS 与进展操作 SHALL 沿用所属项目规则；叙述事实、按日期替换的记录和 0–100 整数进度须分别处理，状态字段领域不得混用。缺负责人、日期、进展或记录不得推断为默认事实。

#### Scenario: 更新部分进展

- **WHEN** 用户只提供一项事实或百分比
- **THEN** 仅更新明确字段并保留其他历史事实；未记录不能写成未开始，缺日期不能判逾期。

### Requirement: F017 重复标识与冲突处理

项目节点重名或标识重复时 SHALL 根据章节和路由消歧，不猜节点；文件被占用或本地冲突时停止写入并报告。删除和归档按项目规则确认，未确认不得批量清理。

#### Scenario: 重复任务编号

- **WHEN** 不同章节中存在相同编号且用户未指明
- **THEN** 展示可辨别章节候选并等待明确目标，不能只凭 ID 改第一项。

### Requirement: F017 周报与只读计划汇总

周报 SHALL 依据当前事实、同步数据与用户确认周期，延续上期计划并保持历史模板；建议与承诺分开。日／周 WBS 和收件箱汇总保持只读，不创建另一份计划、旧计划周期或后台自动化。会议转任务仅在明确要求时执行。

#### Scenario: 生成周报或查看日周事项

- **WHEN** 用户要求周报或只读日周汇总
- **THEN** 按已确认时间范围显示真实事实与建议；不把缺失信息补成承诺，不自动创建任务或调度。
